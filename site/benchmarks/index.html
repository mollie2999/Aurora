Aurora vs official Steam benchmarks on Linux

The official Steam client embeds Chromium and spawns a dozen steamwebhelper processes just to show your library. Aurora draws the entire interface natively in Rust with egui in one process—cutting idle RAM by 8.5× and idle CPU by 90×.

Why does Aurora use so much less RAM and CPU?

No embedded Chromium (steamwebhelper)

Official Steam renders its library, store, chat, and overlays inside Chromium Embedded Framework processes. Even idle in the background, those browser processes hold over 1 GB of memory and continuously wake the CPU.

Aurora talks to Steam's servers directly over Steam's protobuf protocol and draws native widgets on the GPU with egui.

Post-0.7.2 memory & download optimizations

Newer Aurora releases (0.8.x through 1.0.0-rc2) reduced memory further: images decode at display size with a 96 MiB offscreen texture budget, library refreshes fetch only changed apps, minimizing or hiding to tray purges cached textures/heap, and depot downloads use parallel server ranking with SIMD decompression.

Methodology & caveats

What is not measured here: in-game memory while running native Linux or SteamStub DRM games (which start Aurora's windowless steamhost), and native Wayland mode (Aurora ran under XWayland during the benchmark so xdotool could detect window appearance consistently). You can inspect and re-run the exact benchmark script at docs/benchmarks-linux.sh.
